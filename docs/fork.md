# Fork customizations

This fork retains the upstream Pi Web package name and version. Its upstream release base is **v0.13.0**, commit `d128bae47cd3abbdfe7135443ac793f547c14e47` (`d128bae`), with the local customizations below retained.

## Application changes

- Live session rows expose only the **⋯ menu**, not a one-click archive button, to reduce accidental archiving. Archive remains in the menu with Undo; the archive view retains its desktop one-click Restore.

- The tool menu presents **plan / build / full**. Fresh conversations start in build; historical unpinned sessions and legacy API requests also retain build. Changing a conversation's mode does not change the next new conversation's default. A mode selection stays a local draft until ordinary Send submits it with the prompt; running selectors stay visible but disabled. Stop allows drafting the next mode/message immediately but keeps Send disabled until actual task-family unwind. Legacy Chat-only sessions remain tool-free until an explicit user selection crosses their resource boundary at Send.
- Plan and build constrain model tool calls to their builtin allowlists plus vetted subagent/webfetch implementations. Plan permits scout/planner roles; build permits scout/planner/worker/reviewer for complete development workflows. Scout/planner are forced to read-only tools in both plan and build; worker/reviewer keep their role's builtin tools. This is enforced by the trusted external dispatcher when the built-in feature is off, or by a centralized in-process role/resource policy when it is on. The built-in host supersedes the external Web dispatcher without changing terminal configuration. Limited built-in children persist an immutable resource ceiling, load only explicit optional trusted webfetch with isolated resource settings, and recheck current parent permissions on resume/steering. Full otherwise enables all registered, nonhidden tools and keeps upstream profile behavior. This is a model execution policy, **not an operating-system sandbox**.
- Background running conversations receive bounded history prefetch using the existing sidebar poll, without extra SSE streams or starting sessions. Hidden/offline pages pause prefetch. History revisions include the effective upstream notices switch: toggling it invalidates cached messages, while unchanged validation reads only the switch and skips notice scans. Notices settings reads are bounded and non-blocking for both global and project files.
- Reasoning controls use one capability-driven menu. Supported off/on/effort options can save exact SDK-native per-model defaults. Ordinary selections remain session-scoped; model changes restore the target model's saved default without transient display mismatches. Reselecting the current model refreshes saved definitions without reapplying its default effort; native capability clamping and newer explicit effort changes remain authoritative.
- Stable parent-mode instructions describe plan-only investigation/proposals and build/full implementation boundaries, with current declarations authoritative over stale history. Host Stop cancels and awaits built-in background/detached/queued/nested descendants and setup admissions, and suppresses their late completion wakeups; it is distinct from a foreground tool's bounded wait.
- Completion chimes and browser notifications require an observed SDK run and fire exactly once after it settles or is confirmed idle. Handled commands with no run announce nothing; a command handing off a run cannot announce early on `prompt_done`. Stopped runs and unsettled built-in subagent families retain their notification suppression.

Design details and regression boundaries are in [tool policy](agents/tools.md), [built-in subagents](agents/subagents.md#fork-planbuild-policy), [sessions](agents/sessions.md), and [models](agents/models.md).

## Source and deployment separation

This repository contains application code, portable tests, and generic documentation. Machine-specific build/activation helpers, service launchers, deployment records, real configuration, credentials, and sessions are maintained **outside this repository**.

Use the development and test commands in the [README](../README.md). Do not run production builds over a live development or deployed `.next` directory. Publishing this source does not deploy a service or publish an npm package. The npm publish workflow is restricted at job level to `agegr/pi-web`; tags on personal forks cannot publish under the retained upstream package name.
